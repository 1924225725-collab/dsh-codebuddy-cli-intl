在 DeepSeek Harness（DSH）中，使用本机官方 CodeBuddy CLI 的国际站账号可用模型。插件负责转换模型请求和结果，DSH 继续管理对话、权限和工具执行。插件没有中转服务器，也不导入 WorkBuddy 桌面凭据。

## 0.2.0：结构化诊断与独立账号

- 图片流失败会提供固定原因、解析阶段、帧大小和位置、init/result 状态、终止发起方、close 观察状态及总时限状态，帮助区分解析器主动终止与进程自然关闭。
- 原生结果诊断只记录 `structured_output` 是否存在和固定类型、result 类型有效性、有限 subtype 类别，以及已知 CLI 提示的分类与来源；不保存帧内容、stderr 原文或任意字段名和值。
- 配置页和本机日志分别统计用户取消、DSH 图片卸载请求及建议卸载图片数；请求不代表 DSH 已完成卸载。诊断数字使用有界整数白名单。
- 只增强诊断，不放宽 JSONL 事件顺序、唯一 result、原生 Schema、DSH 工具校验或失败边界。没有用户原始帧，原始偶发问题仍待复核。

## 0.1.8 CLI 网络错误识别

- 当无有效模型结果且官方 CLI 错误文本明确包含连接重置、TLS 建立失败或相关 502 时，显示 `CLI_NETWORK_ERROR`，不再误报为普通响应格式错误。
- 使用固定安全提示，不展示原始 stderr、URL 或凭据；插件不会改网络、代理或登录设置，也不会自动重试。
- 配置页与中英故障指南说明该分类只能帮助定位，不能恢复网络或证明具体根因。83 项合成自动检查通过；本版没有发起模型请求，也未复现真实网络故障。

## 0.1.7 工具结果图片

- 接受任意 DSH 工具标准 role=tool 结果中的图片附件，要求消息含有效 toolCallId，图片使用 DSH content 的标准附件引用；没有工具名白名单。仅表示格式兼容，不代表所有第三方工具都已逐个实测。
- 保留 toolCallId、isError 与内容顺序；工具图片和用户图片共用附件 API、5 张/2 MiB/8 MiB 图片预算、DSH 卸载与日志隐私处理。缺少 toolCallId 明确失败；assistant、system、developer 图片仍拒绝。
- 不读取任意本地路径、URL 或裸 Base64；原生音视频、PDF 内容解析、图片生成和工具自定义非标准截图格式未适配。业务工具继续由 DSH 执行。
- 图片通道安全处理官方 CLI error 帧。80 项合成检查通过，新增测试覆盖混合图片、工具单独截图、失败状态和日志隐私；未逐个验证实际桌面/浏览器/第三方截图工具或上传界面。

## 0.1.6 DSH 版本兼容（沿用）

- 支持 DSH 0.2.1-rc.2 与 0.2.1-rc.3；其他 DSH 版本未声明兼容。

## 0.1.5 用户图片输入（沿用）

- 在 0.1.4 原生 JSON Schema 路线上加入图片输入，只对官方动态目录明确标记 `supportsImages` 的模型启用。
- DSH 附件通过本机附件服务读取，并以官方 CLI 原生 stream-json 图片块发送；文本请求继续使用 JSON 输出。CLI 业务工具仍关闭，DSH 继续管理文件、命令及工具执行。
- 每次请求历史最多 5 张图片，单张最多 2 MiB、Base64 合计最多 8 MiB，最长边目标不超过 1920 像素。超限或模型未声明图片能力时明确报错，不静默丢图。
- 图片字节、Base64 和附件标识不会写入日志；诊断只记图片计数和字节数。DSH 已卸载的较早图片不会重新读取。
- 仍只读取唯一最终记录的 `structured_output`，不从自由文本回退；一次 CLI 调用不代表一次推理或固定用量。

**历史验证范围：**0.1.5 的 77 项合成自动检查通过。2026-10-24 使用实际适配器和国际 CLI 对 deepseek-v4.1-flash 完成文字对照及合成 360×240 六色图片识别，均通过且未执行 DSH 业务工具；gpt-5.6-luna 文字对照返回 `CLI_OUTPUT_INVALID`，没有发送图片。0.1.7 对工具结果图片的验证为合成适配器测试，没有发起新模型请求，也没有验收实际 DSH 工具截图或上传界面。未验证所有模型；实际调用仍需有效的国际版 CLI 登录和所选模型权限。

国际版和[国内版](https://github.com/1924225725-collab/dsh-codebuddy-cli-cn)是独立插件，使用独立提供方 ID、区域入口与 CLI 配置目录。国际版版本号独立：最新仓库安装包为 0.2.0；历史正式 Release 为 0.1.8。版本按每段满十进位，不生成 0.1.10。

## 0.2.0 包含的独立账号环境（预览功能）

- 每个账号使用单独的 CLI 配置目录和 Windows 用户目录环境。官方登录由用户在生成的 PowerShell 命令中手动完成，并在官方 CLI 中选择 **International Site**。
- DSH 中带环境备注的模型会固定绑定该环境；切换设置页当前环境不会改变已有会话的账号。鉴权、网络、余额或权限失败后不会轮换账号或回落到默认登录。
- 仅支持 Windows + 官方 npm/Node CodeBuddy CLI `2.174.0`。原生 exe、其他系统和未核查 CLI 版本拒绝使用独立账号功能；普通单账号路径保留。
- 环境统计是 CLI 返回并由插件按环境累计的调用与 Token 数，不是官方账单或余额。可用额度请以官方用量明细为准。
- 同步增加 400 上下文超限、402 余额不足的固定错误分类，并限制内联图片 data URI 总字符数；不会保存图片正文到日志。
- 独立账号候选通过 96 项自动检查。没有登录第二账号、发起模型请求或验证官方扣费归属；详见[多账号指南](docs/多账号使用指南.md)。

## 安装与登录

1. 下载上方 `.tgz` 安装包，在 DSH 插件管理中导入并启用“CodeBuddy CLI（国际版）”。
2. 打开 `llm-codebuddy-cli-intl` 配置页，点击“一键配置 CLI”。已有 CLI 时会检测现有安装；全新安装使用官方国际版安装器或官方 npm 包。
3. 复制登录命令，在 PowerShell 或终端运行 CLI 的 `/login`，选择 **International Site** 并完成官方登录。
4. 返回 DSH，刷新模型与倍率，在会话中选择国际版提供方的模型。先用一条简短消息确认调用，再开始较大任务。

默认 CLI 配置目录为 `~/.dsh-codebuddy-cli-intl`，可在设置中指定其他目录。此目录用于分开放置配置文件，不保证官方 CLI 的系统账号存储也独立。切换账号请使用官方登录流程。

## 故障处理与隐私

常见情况和操作步骤见[完整指南](docs/使用与故障处理指南.md)。插件自动保存最近 100 次调用的基础诊断，日志文件最多 2 MiB；基础日志不包含请求或回复正文、CLI 标准错误、登录凭据和配置路径。日志不会自动上传。

需要排查原始回复时，可在设置页阅读提示后手动开启一次失败采集。采集范围最多 256 KiB，仅包含模型返回，不包含请求、登录文件或 CLI 标准错误。分享前请预览并检查全部内容，删除私人信息。

## 工作流程与限制

![DSH、插件与官方 CLI 调用流程](docs/images/architecture.svg)

CLI 使用国际站公开环境并在本机运行；插件不直接请求 CodeBuddy 服务。文本和已声明支持的图片由官方 CLI 处理，DSH 负责执行工具。余额请在官方账号页面查看；本插件不读取账单，也不把 Token 数换算为积分。

这是第三方适配项目，不代表官方背书或账号安全保证。模型权限、可用额度与服务规则由官方账号和服务决定。
