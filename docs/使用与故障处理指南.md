# 使用与故障处理指南

[English](USER_GUIDE.en.md) · [安装说明](安装教程.md) · [返回首页](../README.md)

适用于公开版 0.1.8 与本地预览 0.2.1。插件配置页中的“故障处理与使用指南”提供离线可读的要点；本页是完整说明。

## 先确认失败发生在哪一步

插件把模型回复转换成 DSH 文字与工具请求，文件和命令仍由 DSH 执行。最终回复失败，并不会撤销此前已经完成的工具操作。重试前先查看 DSH 的工具记录、实际文件内容和命令退出码。

如果错误提示“本次结果未交付工具调用”，指的是报错的这一次模型结果；不能据此认定整个多步骤任务没有修改过文件。插件不会因格式错误自动重新请求模型或重跑工具。

## 常见提示与处理方法

| 提示或现象 | 什么情况下会出现 | 建议处理 |
| --- | --- | --- |
| `native-final-results` | CLI 输出中最终结果记录为零条或多条，包括内容相同的重复记录 | 不要选择最后一份或合并。核对已完成操作，用简短新对话提供必要摘要，只请求下一项明确动作；仍失败时先采集原文再反馈 |
| `CLI_STRUCTURED_OUTPUT_MISSING` | CLI 未返回官方 `structured_output` 字段 | 检查国际 CLI、账号和模型是否支持该次输出；插件不会用自由文本或 `result` 替代。拆小请求并确认已完成工具后再试 |
| `invalid-json`、字段类型错误 | CLI JSON 无效，或原生对象字段与 schema 协议不符 | 保留错误码和诊断 ID。原生结构对象不会再从文本扫描、修复转义或补字段；先核对已完成的工具操作 |
| `TOOL_CALL_INVALID` | 工具名没有声明，或工具参数不是有效对象 | 确认当前 DSH 工具已启用，并把任务写清楚。不要将未知名称改成某个相近工具后执行；反馈所用 DSH/CLI/插件版本 |
| 最后提示失败，但命令已有输出 | 工具已成功，随后模型汇总或下一步回复失败 | 查看输出、退出码和文件状态；如果只缺总结，明确请求“仅汇总已提供的结果，不重复操作” |
| 代码块、引号或路径不完全一致 | 模型可能多写、少写转义字符或改动了文字 | 只要求重写有差异的一小段并逐字符核对。插件不会对合法 text 统一二次反转义；不要直接执行未经确认的内容 |
| `CLI_AUTH_REQUIRED`、401 | 官方 CLI 的登录或授权失效 | 从配置页复制官方登录命令，在 CLI 执行 `/login` 并选择 **International Site**，再验证一次短请求。插件不能恢复账号权限或额度 |
| `CLI_CONTEXT_TOO_LARGE`、400 | 官方服务判定请求超过上下文上限 | 新建较短对话，整理必要摘要并减少历史内容；不要反复重发同一份过长请求 |
| `REQUEST_TOO_LARGE` | 本机在启动 CLI 模型调用前拒绝了请求 | 查看配置页或普通日志中的阶段、实际 UTF-8 字节、上限和尺寸分解。国际版文字封装上限为 12 MiB；图片模式最终 stream-json 输入上限为 24 MiB。它与官方服务返回的 400 上下文错误不同。插件不会自动删除历史、丢弃图片、截断 Schema、切换模型或重试 |
| `CLI_INSUFFICIENT_BALANCE`、402 | 官方服务报告余额或可用额度不足 | 在官方用量明细核对账号、模型权限和剩余额度。号池不会自动切换账号；本机统计不是官方账单 |
| `CLI_NETWORK_ERROR` | 无有效结果，且 CLI 错误文本符合已知连接重置、TLS 建立失败或相关 502 模式 | 检查当前网络到 CodeBuddy 官方国际服务的连通性和代理设置。此分类只识别已知 CLI 文本，不能修复网络或证明具体原因；插件不会自动重试。核对已完成的 DSH 操作后，再自行决定是否重试 |
| `CLI_TIMEOUT` | 整次 CLI 调用超过设置时限，包含启动、模型处理与进程退出 | 拆分任务，检查官方服务与网络，按需提高总时限。增加时限不能解决冲突 JSON；重试前仍要确认此前操作 |
| `IMAGE_MODEL_UNSUPPORTED` | 当前模型目录没有明确声明图片能力 | 刷新模型目录并选择标记支持图片的模型；未声明的模型会拒绝图片请求，不会静默删图 |
| `IMAGE_OFFLOAD_REQUIRED`、`IMAGE_TOO_LARGE` | 图片数量、累计 Base64 或单张转换后大小超过插件限制 | 减少或缩小图片；必要时新建较短会话。已由 DSH 卸载的旧图不会重新发送 |
| `IMAGE_READ_FAILED`、`IMAGE_SERVICE_UNAVAILABLE` | DSH 附件服务无法提供图像版本，或当前 DSH 没有图片读取能力 | 检查图片是否仍在当前对话，更新 DSH 附件组件并重新上传；失败时不会发送不完整图片 |
| 文件找不到、`grantWrite`、ACL 或权限错误 | 工作区选错、路径不存在，或 DSH/Windows 工具环境拒绝访问 | 先在资源管理器核对工作区和路径，按实际 DSH 权限策略处理。不要把权限错误直接归为模型格式错误，也不要为修复格式而修改权限 |

## 原生结构输出边界

适配器每个 DSH 请求启动一个 CLI 进程，只读取唯一最终结果记录里的 `structured_output`，并严格要求顶层只有 `text` 和 `toolCalls`。每轮都必须提交本次唯一的原生 `StructuredOutput` 结果；历史 assistant `tool-call` 是先前 DSH 提案，历史 `tool` 消息是 DSH 已返回的结果。本轮新返回的 `toolCalls` 仍是提案，尚未由 DSH 执行。缺少字段、无效结构、未声明工具、非对象参数或零条/多条最终记录都会失败。即使两条记录看起来相同，也不会去重或选择其中一条。单个有效计划中重复出现的工具调用会按原顺序保留。

图片请求仅在动态模型目录声明 `supportsImages` 时启用，并用 CLI 原生 stream-json 图片块发送；纯文本请求保留现有 JSON 输出通道。每次请求历史最多 5 张图片，单张最多 2 MiB，Base64 合计最多 8 MiB，目标长边不超过 1920 像素。图片内容与附件 ID 不进入日志。实现细节见[图片输入说明](IMAGE-INPUT.md)。

DSH 请求内联携带的图片 data URI 另有 32,768 字符的合计上限，超出时会在本机拒绝请求；诊断只保留计数，不保留 URI 内容。0.1.9 的独立账号环境仅支持 Windows + 经核查的官方 npm/Node CLI 2.174.0，配置与限制见[多账号使用指南](多账号使用指南.md)。真实多账号登录、刷新和扣费归属尚未验证。

0.2.0 预览为图片 JSONL 失败记录固定原因、解析阶段、帧序号和字节数、init/result 计数、最后帧类别，以及进程终止由谁发起、是否观察到 `close`、是否达到总时限。它也记录原生 `structured_output` 是否存在和固定类型、`result` 类型是否有效、有限 subtype 类别，以及已知 CLI 提示的分类与来源。普通日志只保存固定字段，不保存图片帧、原始 stderr、任意 subtype 或字段内容。增强诊断不改变协议验收，也不能单独证明用户原始偶发故障的根因。

0.2.1 预览在本机拒绝超限请求前记录安全的尺寸事实：文字封装包括 `promptBytes`、系统、历史、工具、响应 Schema 和固定封装开销；图片模式另记录最终 stream-json 输入字节数。国际版仍使用 12 MiB 文字封装上限和 24 MiB 图片 CLI 输入上限。超限本机拒绝的实际字节、检查阶段和上限会进入运行状态与普通日志；旧日志中缺少的尺寸无法补算。尺寸是 UTF-8 字节，不是 Token 或官方账单数据。它只解释本地检查，不证明上游超限根因，也不自动压缩或移除历史、丢图、裁 Schema、切模型或重试。

配置页按插件运行周期分别统计用户主动取消次数、DSH 图片卸载请求次数、请求卸载图片张数，以及请求历史中已标记卸载的图片数；这些计数在重启后归零。卸载请求不是已完成卸载的确认，插件不会自行删除图片历史。逐次日志只保存有限字段与有界整数，不保存图片内容或帧正文。

CLI 进程使用 `--max-turns 4` 限制内部结构化处理轮次。一次 CLI 启动不代表恰好一次模型推理或固定用量；以官方用量明细为准。插件不会追加模型修复请求或重放已完成的 DSH 工具。

## 长对话中减少再次失败

历史会话同时包含代码、工具结果、旧指令和多次失败时，模型可能难以保持输出约束；长历史只是影响因素之一，不是每次失败的已证实根因。反复失败时，新建对话并提供简短、准确的任务摘要：已完成什么、当前文件在哪里、哪些操作不能重复、下一步只做什么。不要仅靠不断发送继续来反复触发同一任务。

一次处理一个清楚的动作或小批次。需要长文件时，先规划再分段读改，避免要求一次输出全部文件。以上做法减少负担，但不保证特定模型永不出错。

## 如何保留能定位问题的日志

1. 在插件 `dsh-codebuddy-cli-intl` → 组件 `llm-codebuddy-cli-intl` 配置页找到“诊断日志与问题反馈”，记录运行版本。
2. 导出普通日志，附完整错误、诊断 ID、时间、模型与推理设置，以及复现步骤。普通日志不保存聊天或回复正文。
3. 需要查看原始模型返回时，先阅读提示并手动开启“采集下一次失败回复”，再复现一次。无法补录开启前的原文。
4. 成功调用和主动停止任务不消耗采集机会；下一次非主动取消的失败会结束本次采集。取消采集、清空日志或重启也会关闭开关。没有模型正文的启动/登录错误可能无法产生详细样本。
5. 预览详细样本，检查导出文件中的全部内容并移除私人信息后再分享。详细样本最多 256 KiB，超出保留首尾；标记为截断的样本不代表日志里有完整原文。日志不会自动上传。

国际 CLI 登录时，在官方登录方式中选择 **International Site**。看到错误后先保留必要的诊断信息，再决定是否重试；不要以“后来成功了一次”替代对原失败原因的核对。
