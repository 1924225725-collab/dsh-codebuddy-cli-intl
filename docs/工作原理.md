# 工作原理 / Architecture

DSH 提供历史和工具说明 → 本地插件转换为受约束的提示与 JSON Schema → 官方 CLI `--print --output-format json --json-schema … --tools StructuredOutput` → 官方国际服务 → 插件读取并验证 `structured_output` → 文字或 DSH 工具请求返回 DSH。

CLI 唯一启用的内置工具是 `StructuredOutput`，仅用于提交受 JSON Schema 约束的结果；文件、命令、网络等业务工具及 MCP 均关闭。有限的 CLI 结构处理轮次受上限约束，并继续使用插件配置的超时和取消信号。

插件只读取唯一最终结果记录中的 `structured_output`，再严格验证 `{ text, toolCalls }` 对象。普通 `result` 文本不作替代；缺字段、格式不符或最终记录不是唯一一条都会报错，包括内容相同的重复记录。不会扫描文本、静默回退旧协议、自动追加模型修复请求或重放已完成工具。单个结构结果内部有序重复的 DSH 工具调用会原样保留。

每个 DSH 请求由适配器启动一个 CLI 进程。`--max-turns 4` 限制 CLI 内部的结构化处理轮次；这不等于每个请求只发生一次模型推理或固定用量，实际消耗以官方用量明细为准。插件保留整体超时和取消信号。

DSH 的工具白名单和参数对象检查仍由插件执行；工具只由 DSH 执行，工具结果与错误历史传回下一轮。插件不是通用 HTTP API 服务；本机状态接口用于配置页。账户认证和远端请求由官方 CLI 完成。配置目录、提供方 ID、安装和日志目录仍与国内插件分开。
